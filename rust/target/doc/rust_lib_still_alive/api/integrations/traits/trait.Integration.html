Expand description

Platform-specific integration implementation.

The important distinction is that discovery does NOT mutate persisted configuration. The user first discovers available destinations and then explicitly selects which destinations should be persisted.

fn authenticate_account( &self, credential: &str, ) -> impl Future<Output = Result<IntegrationAccount>> + Send

Authenticates a provider credential and returns the corresponding account.

This does not persist anything. Persistence is performed by add_account.

Source

fn discover_destinations( &mut self, account_id: &str, ) -> impl Future<Output = Result<Vec<MessageDestination>>> + Send

Discovers destinations available to an account and reconciles the account’s persisted destinations with the provider.

Persisted destinations that are no longer accessible are removed. Persisted destination names are updated when they differ from the provider’s current name.

fn test_destination( &self, account_id: &str, destination_id: &str, ) -> impl Future<Output = Result<DestinationTestResult>> + Send

Tests whether a specific destination can currently receive a message.

This must verify both:

  1. The destination is explicitly selected for the account.
  2. The provider currently allows the connected account to send to it.

Implementations should avoid actually sending a user-visible message. Provider-specific permission/access checks should be used where possible.
